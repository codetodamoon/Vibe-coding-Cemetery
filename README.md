# 🪦 Vibe-coding-Cemetery

> **给你的"Vibe-coded"失败作品一个体面的葬礼。**

在 Vibe Coding 的时代，每个人都在 X (Twitter) 上展示自己如何用自然语言在 5 分钟内撸出了一个独角兽 Demo。但没人告诉你，在那 1 个成功的背后，还躺着 99 个死掉的仓库。

这些项目可能因为 **Prompt 跑偏**、**模型幻觉**、**伪需求**、或者单纯因为你**在那 5 分钟的狂热之后突然清醒了**而夭折。

**别删仓库！把它们埋在这里。** 这里是失败的博物馆，是代码的墓地，也是后来者的避坑指南。

-----

## 🏛️ 墓地分区 (Categories)

我们根据项目的"死因"设置了四个主要墓区：

* **🐣 胎死腹中 (Stillborn):** 只有几行被 AI 搞乱的代码和一份宏伟的 README。作者在中途意识到 Vibe 不下去了，项目进度 \< 10%。
* **💎 美丽废物 (Beautiful Junk):** UI 惊艳，逻辑通顺，功能完备。但做完之后你对着屏幕陷入了沉思："这玩意儿到底有什么卵用？"
* **🌀 智障 AI (AI Hallucination):** 典型的"被 AI 坑了"。模型信誓旦旦地给了你一套不存在的 API 或逻辑，你 Debug 了三个小时后选择原地放弃。
* **📉 商业幻觉 (Market Fail):** 产品完美，逻辑闭环，但推向市场（或发给朋友）后发现，这世界根本不需要它。

-----

## 🕯️ 为什么要提交？

1.  **消除焦虑：** 记录失败是缓解"幸存者偏差"焦虑的最好方式。告诉大家：大佬也会翻车。
2.  **反向教学：** 成功的路径有很多，但大坑往往就那几个。你的失败经验比成功案例更具启发性。
3.  **拥抱不确定性：** 构建一个系统来捕获随机发生的价值。即使是失败的代码，在某个时刻也可能成为另一个项目的基石。
4.  **人味儿：** 在 AI 批量产出内容的时代，承认失败是人类最真实、最有力量的行为。

-----

## 📝 葬礼流程 (How to Contribute)

本项目已实现 **全自动化安葬流程**。你只需要提交一个 Issue，系统会自动为你修筑墓碑。

1.  点击本仓库的 **New Issue** 按钮。
2.  选择 **Bury My Project** 模板，填写你的"尸检报告"。
3.  **提交 Issue。** Maintainer 审核通过后：
      * 你的 Issue 会被打上 `approved` 标签并关闭。
      * 系统自动在对应目录下生成你的项目详情页。
      * 你的项目会自动出现在下方的索引表格中。

**审核标准：** Maintainer 会检查内容是否符合墓园调性（拒绝恶意或无意义的提交）。

**无需 Fork，无需写代码。** 提交 Issue = 提交墓碑。
